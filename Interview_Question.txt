6. If we put width greater than max-width?
=> 
   If both width and max-width are specified, and the width value is greater than max-width, the browser uses the max-width value as the final rendered width.

   max-width acts as an upper limit.

   If width is smaller than min-width, min-width wins.
   If width is larger than max-width, max-width wins.
   Otherwise, width is used.

7. use of auto width?
=> 
   width: auto is the default width behavior for most elements. It means:
   "Let the browser determine the width based on the element type, content, and layout context."
   
8. What is the difference between w-auto and w-full?
=> 
   width: auto lets the browser calculate the element's width automatically based on its content, display type, and available space. For block elements it usually fills the available horizontal space, while for inline elements it typically shrinks to fit the content. It is the default value of the CSS width property.

   width: 100%, Takes the full width of the parent container.

9. What is the view port?
=> 
   The viewport is the visible area of a web page inside the browser window.
   It is the portion of the page the user can currently see
   It does not include the browser UI (tabs, address bar, bookmarks)
   Its size changes based on device (mobile, tablet, desktop) and window resizing


10. The difference between h-screen and h-full?
=> 
   h-screen : 
              Sets element height to 100% of viewport height
              Equivalent to: height: 100vh

   h-full : 
             Sets element height to 100% of its parent’s height
             Depends on parent having a defined height
             If parent height is not set → h-full may not work as expected
             Equivalent to: height: 100%


   | Feature        | `h-screen`           | `h-full`                 |
   | -------------- | -------------------- | ------------------------ |
   | Reference      | Viewport             | Parent element           |
   | CSS equivalent | `100vh`              | `100%`                   |
   | Dependency     | Independent          | Depends on parent height |
   | Use case       | Full-screen sections | Fill container space     |
   | Reliability    | Always consistent    | Requires parent height   |


11. If asked “What are sizes in Tailwind?”, answer like this?
=> 
   Tailwind uses a utility-first spacing scale (based on rem units) that controls sizing across width, height, margin, padding, gap, and constraints. It ensures consistency by mapping numeric classes to fixed values (e.g., 4 = 1rem). It also provides semantic sizes like full, screen, auto, and fractional widths for layout control.


12. What is the container utility in Tailwind CSS?
=> 
   he container utility in Tailwind CSS is a layout helper that sets a max-width based on the current responsive breakpoint, while centering the content using auto margins.
   It does not behave like a fixed width; instead it adapts across screen sizes.

13. What are the default container breakpoints in Tailwind CSS?
=> 
   The container’s max-width changes at Tailwind’s default breakpoints:

   sm: 640px
   md: 768px
   lg: 1024px
   xl: 1280px
   2xl: 1536px

   So the container expands step-by-step as viewport width increases.

   You can customize this in tailwind.config.js using theme.container.

14. What is the difference between responsive breakpoints and container breakpoints?
=> 
   Responsive breakpoints (viewport-based):
   Based on screen size
   Use utilities like md:bg-red-500
   Example: applies when browser width ≥ 768px

   Container breakpoints (container-based):
   Based on parent container width, not viewport
   Use container queries like @md, @lg
   Example: applies when a div is ≥ 768px wide, even inside a small screen

15. What are container queries in Tailwind CSS v4
=> 
   Container queries allow styles to change based on the size of a parent element rather than the screen.

      <div class="@container">
         <div class="@md:text-lg @sm:text-sm">
            Responsive to container size
         </div>
      </div>

      This is not viewport responsiveness.

      It means:

      “Typography scales based on the parent component width, not the screen size.”

16. last matching rule wins
=> 
   <div class="@sm:text-sm @md:text-xl @lg:text-3xl">

   And container width = 1100px

   Then: @sm → true
         @md → true
         @lg → true

         👉 All apply, but CSS cascade decides final output:

         the last matching rule in stylesheet wins, so @lg:text-3xl wins.

         @md means container element width ≥ md


17. What is the difference between bg-cover and bg-contain?
=> 
   bg-cover: Scales image to cover the entire element, may crop parts.
   bg-contain: Scales image to fit inside element without cropping, may leave empty space.

   Use cover for hero sections and contain for logos or full-image visibility.


18. What is the difference between bg-fixed and bg-scroll?
=> 
   bg-fixed: Background stays fixed relative to viewport.
   bg-scroll: Background moves with page scroll (default behavior).

   Used mainly for parallax-like effects.


19. What does background-size: cover do?
=> 
   It scales the background image so it completely covers the element’s area while maintaining aspect ratio. Some parts may be cropped.

20. When would you use container vs bg-cover in a real project?
=> 
   Use container for page layout like headers, sections, and grids.
   Use bg-cover for hero sections, banners, and full-screen background images.

21. how to disable filter in tailwind css?
=> 
   In Tailwind CSS v4, you disable all applied CSS filters using the filter-none utility.

   Example : <img class="blur-md brightness-150 filter-none" />

   Disable filters at a breakpoint : <img class="blur-md brightness-125 md:filter-none" />


22. difference between focus and Active? answer as interview
=> 
   :focus is the state when an element has input focus and can receive keyboard events, 
   while :active is a temporary state that exists only while the user is pressing or activating the element.

   | Pseudo-class | When it Applies                                                                       |
   | ------------ | ------------------------------------------------------------------------------------- |
   | `:focus`     | When an element has keyboard or input focus.                                          |
   | `:active`    | While the element is being activated (typically during a mouse click or touch press). |
